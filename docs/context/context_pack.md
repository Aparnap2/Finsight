# Finance Context Pack

## Purpose

The **Finance Context Pack** is the structured collection of financial data assembled for each pipeline run. It provides the LLM with all relevant information needed to generate accurate, grounded commentary — without ever exposing raw database records. The context pack is the bridge between deterministic pipeline outputs (assertions, variances, materiality assessments) and the natural language commentary generated by the agent layer.

## Core Principle: Never Send Raw Data to the LLM

Raw financial data (database rows, unprocessed journal entries, full account lists) must **never** be included in LLM context. Instead, the context pack contains:

- **Aggregated and summarized** data (totals, subtotals, percentages).
- **Pre-computed analytics** (variances, materiality assessments, bridge analyses).
- **Assertions** — structured, grounded claims with evidence IDs.
- **Qualitative context** — business notes, known risks, accounting policies.

This approach minimizes token usage, reduces hallucination risk, and ensures the LLM works with validated information rather than raw numbers it might misinterpret.

## Context Pack Structure

### 1. Company Context

Basic identifying information about the legal entity being analyzed.

```json
{
  "company": {
    "id": "CF001",
    "name": "Acme Corp",
    "currency": "USD",
    "fiscal_year_start": "2025-01-01",
    "fiscal_year_end": "2025-12-31"
  }
}
```

**Included fields**: Company ID, name, base currency, fiscal year boundaries.

### 2. Fiscal Period

The period or periods under analysis.

```json
{
  "fiscal_period": {
    "id": "FP-2025-03",
    "fiscal_year": 2025,
    "fiscal_period": 3,
    "period_type": "monthly",
    "start_date": "2025-03-01",
    "end_date": "2025-03-31",
    "status": "analyzing"
  }
}
```

**Included fields**: Period ID, fiscal year, period number, type (monthly/quarterly/annual), date range, status.

**Multiple periods**: For YTD or cumulative analyses, the context pack includes all relevant periods with their individual summaries.

### 3. Budget Data

Budget values for the current period and YTD.

```json
{
  "budget": {
    "version": "v2_revised",
    "revision_reason": "Q2 reforecast — updated revenue targets",
    "total_revenue": 12500000,
    "total_cogs": 5500000,
    "total_opex": 4200000,
    "total_ebitda": 2800000,
    "by_department": [
      {"department": "Sales", "budget": 1800000},
      {"department": "R&D", "budget": 1400000},
      {"department": "G&A", "budget": 1000000}
    ]
  }
}
```

**Included fields**: Budget version details, total by major category, department-level breakdown. Not included: individual line-item accounts (rolled up).

### 4. Actual Data

Actual financial results for the current period and YTD.

```json
{
  "actuals": {
    "total_revenue": 11800000,
    "total_cogs": 5750000,
    "total_opex": 4350000,
    "total_ebitda": 2450000,
    "data_completeness": 0.95,
    "data_quality_score": 0.88,
    "by_department": [
      {"department": "Sales", "actual": 1750000},
      {"department": "R&D", "actual": 1500000},
      {"department": "G&A", "actual": 1100000}
    ]
  }
}
```

**Included fields**: Total by major category, department-level breakdown, data completeness and quality scores.

### 5. Forecast

Forward-looking projections (when applicable).

```json
{
  "forecast": {
    "method": "rolling",
    "horizon_months": 12,
    "base_case_revenue": 51000000,
    "optimistic_revenue": 53500000,
    "pessimistic_revenue": 48500000,
    "confidence_score": 0.75
  }
}
```

**Included fields**: Method, horizon, scenario values, confidence score.

### 6. Historical Trends

Prior period comparisons for trend context.

```json
{
  "historical_trends": {
    "revenue_growth_yoy": "8.2%",
    "cogs_as_pct_revenue": {
      "current_period": 48.7,
      "prior_period": 46.5,
      "prior_year_period": 45.2
    },
    "opex_trend_quarters": [4100000, 4150000, 4250000, 4350000]
  }
}
```

**Included fields**: YoY growth rates, margin trends, multi-period trend series.

### 7. Material Variances Identified

Pre-computed list of variances that exceed materiality thresholds. This is the primary input for root cause analysis.

```json
{
  "material_variances": [
    {
      "account_id": "4100",
      "account_name": "Product Revenue",
      "tier": "CRITICAL",
      "variance_amount": -450000,
      "variance_pct": -8.2,
      "is_favorable": false,
      "bridge_analysis": {
        "price_effect": -120000,
        "volume_effect": -280000,
        "mix_effect": -50000,
        "fx_effect": 0,
        "reconciles": true
      }
    }
  ]
}
```

**Included fields**: Only material variances (filtered by materiality engine), with bridge decomposition where available.

### 8. KPI Values with Trends

Key Performance Indicators relevant to the fiscal period.

```json
{
  "kpis": [
    {"name": "Gross Margin %", "value": 51.3, "trend": "decreasing", "prior_period": 53.5},
    {"name": "Burn Rate", "value": 1200000, "trend": "stable", "prior_period": 1250000},
    {"name": "Headcount", "value": 450, "trend": "increasing", "prior_period": 420}
  ]
}
```

**Included fields**: KPI name, current value, trend direction, prior period value.

### 9. Business Drivers

Current driver values and changes from prior periods.

```json
{
  "drivers": [
    {"name": "Sales Headcount", "current": 85, "prior": 80, "change": "+6.3%"},
    {"name": "Avg Deal Size", "current": 45000, "prior": 42000, "change": "+7.1%"},
    {"name": "Win Rate", "current": 0.28, "prior": 0.32, "change": "-12.5%"}
  ]
}
```

**Included fields**: Driver name, current and prior values, percentage change.

### 10. Accounting Policies

Applicable policies that may affect interpretation of variances.

```json
{
  "accounting_policies": [
    "Revenue recognition: ASC 606 — recognize upon delivery",
    "FX translation: Period-end spot rate for balance sheet, average rate for P&L"
  ]
}
```

### 11. Known Risks

Pre-identified risks affecting current or future periods.

```json
{
  "known_risks": [
    {"risk": "Supply chain disruption — lead times increased 2 weeks", "impact": "COGS may increase 3-5% in Q3"},
    {"risk": "Currency volatility — USD/EUR ±5%", "impact": "FX variance in European revenue"}
  ]
}
```

### 12. Previous Commentary

Most recent commentary for continuity.

```json
{
  "previous_commentary": {
    "last_period": "2025-02",
    "key_points": [
      "Revenue shortfall driven by lower Enterprise volume",
      "OpEx increase due to annual bonus accrual",
      "Gross margin compression from higher material costs"
    ]
  }
}
```

### 13. Business Context Notes

Free-form business context provided by the FP&A team.

```json
{
  "business_context": [
    "New CEO started March 1 — restructuring expected",
    "Major customer contract renewal in Q3 — $5M at risk",
    "Facility consolidation underway — moving to single HQ by Q4"
  ]
}
```

## Assembly Rules

1. **Only material variances** are included — the materiality engine filters out sub-threshold variances before the context pack is assembled.
2. **Totals must reconcile** — budget total must equal sum of department budgets (within \$1 tolerance). If not, the context pack notes the reconciliation gap.
3. **Data quality annotations** accompany any section where quality checks failed.
4. **Token budget** — the context pack should not exceed 4,000 tokens for a standard monthly analysis. Sections beyond this are truncated with a note.
5. **Degraded modes** — if the pipeline ran in a degraded mode (e.g., missing FX data), the affected sections include a degraded mode annotation.
